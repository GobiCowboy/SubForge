# 口播音频切分测试：有效字数规则

测试音频：`/Users/jago/Documents/vedio/06_subforge/Sub forge演示.mp3`

测试模型：`qwen3-asr-flash-filetrans`

测试脚本：`script/test_qwen_segment_rules.py`

## 本次规则

- 不跨越 ASR segment。
- 一级标点 `。！？!?；;，,` 直接作为切分边界。
- 顿号 `、`、冒号 `：:` 平时不主动切分；一级片段超长时，向前寻找最近的二级标点。
- 标点不计入字数。
- 语气词/语气助词 `嗯、呃、额、哦、噢、哎、唉、呢、啊、呀、吧、嘛` 不计入字数。
- 带标点、单独出现的“好”按语气词处理；“好吃”“好用”等正常词语不按语气词处理。
- 有效字数少于 3 时，优先向后合并。
- 当前 ASR segment 已经结束时，不能为了合并短片段而跨到下一个 segment；只能保留，或在本 segment 内向前合并。
- 最大长度为 32 个有效字。

## 统计

- ASR segment：59 个
- 规则切分结果：167 条
- 当前结果没有跨越 ASR segment

## 关键结果

### 语气词后的边界

ASR 字级时间戳中的原始顺序是：

```text
一般来说呢，｜呃，｜添加字幕是整个视频的收尾阶段。
```

当前结果：

```text
一般来说呢，
呃，添加字幕是整个视频的收尾阶段。
```

这说明标点切分本身先正确发生了，之后的短片段“呃，”被向后合并，没有再吞回上一句。

### “粘贴，哎？”类型的短片段

在同一个 ASR segment 内，如果出现：

```text
粘贴，｜哎？｜后面的内容
```

由于“粘贴，哎？”只有 2 个有效字，结果会向后合并：

```text
粘贴，哎？后面的内容
```

但本次音频中“粘贴。”和“哎，过程就完了。”恰好属于两个 ASR segment，因此不能跨段合并。这是当前硬约束下的正确结果：

```text
48. [118.08-119.92] 回到起始帧，粘贴。
49. [119.92-121.04] 哎，过程就完了。
```

### 跨 segment 的短句

“我们。”只有 2 个有效字，但下一句已经属于新的 ASR segment，因此保留为短句，不跨段吞并：

```text
30. [66.44-69.24] 就把时间戳给复制下来了。
31. [69.24-69.40] 我们。
32. [77.96-79.72] 可以用Tab键呢来不断的切换，
```
