# 310 版本内容发布系统

## 1. 功能目标

为 SubForge 提供稳定的使用帮助、最新动态和版本检查入口，让用户在安装后能看到与当前 App 版本匹配的使用说明，并在新版本发布后了解更新价值。

## 2. 入口与范围

包含：

- 顶部菜单「帮助」中的「使用帮助」「版本更新」；
- 主工作区侧边栏底部的「使用说明与更新」统一入口；
- 菜单栏中的「使用说明与更新」辅助入口；
- 版本化帮助、最新动态、更新检查和外部下载页跳转；「最新动态」负责阅读，「检查更新」负责状态与跳转，两者不展示同一组操作信息；
- 使用说明与更新页面提供与「使用帮助」「最新动态」「检查更新」同级的「意见反馈」入口，通过邮件发送功能建议、问题反馈或体验意见；
- 启动异步检查、一次性更新提醒、本地缓存和离线内置帮助。

不包含：

- 应用内自动替换安装包；
- 远程代码执行或远程功能开关；
- 用户账号、行为分析和客服系统。

## 3. 内容源决策

- 唯一源文件位于项目根目录 `release-content/`，通过 Git 管理；
- 正式部署由 Astro_Blog 承载到：
  `https://gobicowboy.cn/projects/subforge/content/`；
- GitHub、GitHub Releases 和 GitHub Pages 不作为 App 运行时内容地址；
- App Store 与 Developer ID 使用不同的正式下载地址；
- `manifest.json` 按分发渠道声明最新版本，避免 App Store 版本误提示站外版本。

## 4. 内容模型

- `manifest.json`：索引、渠道最新版本、内容 URL 和 SHA-256；
- `releases/<version>.json`：版本标题、日期、更新亮点和演示视频；
- `help/<help-version>.json`：快速开始、能力说明和常见问题；正文支持兼容旧格式的 `body` / `bullets`，以及带 `style`、`icon` 的结构化 `blocks`（步骤、提示卡片、图片）；
- `media/`：帮助图片等静态媒体；图片必须声明 `sha256`，客户端按内容哈希缓存和校验；
- 历史内容不覆盖、不删除；帮助内容修订时生成新的哈希地址。

## 5. 关键交互

- 启动后在主界面可用后异步检查，不阻塞启动；
- 新版本只自动提示一次，点击「稍后」后记录 `lastSeenAvailableVersion`；
- 手动检查始终展示同一套更新内容；
- 无网络、超时、无效 JSON 或哈希不匹配时回退缓存，首次安装回退内置帮助；
- 「去更新」只使用内容清单声明的正式下载页。
- 「提交意见」预填产品名、App 版本、macOS 平台、反馈类型和当前页面，不自动附加日志、截图或媒体。

## 6. 验收标准

- [x] 菜单有「使用帮助」「最新动态」「检查更新」三个入口；最新动态负责阅读，检查更新负责版本状态、更新按钮和历史记录；
- [x] 侧边栏和菜单栏有「使用说明与更新」统一入口；
- [x] 帮助内容与本机版本匹配；
- [x] 版本比较使用语义版本，不使用普通字符串比较；
- [x] 启动提示同一远程版本只出现一次；
- [x] 远程内容经过 schema、appID、版本和 SHA-256 校验；
- [x] 离线时应用仍可正常使用并显示内置帮助；
- [x] 更新按钮只打开正式下载页。
- [x] 使用说明与更新页面有邮件反馈入口，收件地址为 `guojin.writer@outlook.com`。
